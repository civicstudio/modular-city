Open records

Check a city record

You shouldn't have to take the city's word for what a record says. Every record Modular City publishes this way has a fingerprint: a short code computed from the file's exact contents. If one character of the file changes, the fingerprint changes completely. You can recompute it yourself, on your own computer, and compare.

This is a worked example with fictional records

Modular City is a model city, and the minutes below describe no real meeting. The example has not been anchored on a public blockchain yet, and the credential is unsigned. Everything on this page is computed from files you can download here, so every check works today.

1. Check the minutes yourself

  1. Download {{ ex.artifact.title }} (plain text).

  2. Compute its SHA-256 fingerprint with the tool your computer already has.

    Mac or Linux terminal
    shasum -a 256 2025-01-14-city-council-minutes.txt
    Windows PowerShell
    Get-FileHash 2025-01-14-city-council-minutes.txt -Algorithm SHA256

  3. Compare the result with the fingerprint the city published. Windows prints it in capital letters, which is the same value.

    Published fingerprint of the adopted minutes

    {{ ex.artifact.sha256 }}

If the two match, you hold exactly the file the Council adopted. If they differ, the file was changed after it was published.

2. How one fingerprint covers a whole day

Writing every record to a public blockchain one at a time would be slow and wasteful. Instead, Public Registry gathers each day's records into one fingerprint, called the day's root. Only the root goes on chain, in one small transaction a day, once the registry's anchoring is funded. No names, addresses or other personal details go on chain, only fingerprints.

  1. The minutes' fingerprint is named in a short anchor credential (JSON) that says who published the file and when.
  2. The credential's own fingerprint becomes one leaf of that day's tree.
  3. The leaves are combined in pairs, and pairs of pairs, until one root is left. The registry uses the Certificate Transparency method (RFC 6962) with SHA-256.
  4. An inclusion proof lists the few values you need to walk from one leaf up to the root, without seeing the other records.

What a fingerprint proves, and what it doesn't

  • A matching fingerprint proves the file is unchanged since it was fingerprinted.
  • An anchored day root proves the fingerprint existed by the time that transaction was mined, and that nobody has quietly edited the day since.
  • A signature from the city's published key proves who issued the record. Modular City will add signed records once the registry's permanent keys are in place.
  • None of this proves the minutes are accurate. That still rests on the Council adopting them in public, which is why the record names the meeting.
